# BP の振動と正規化失敗の調査（2026-11-09）

更新式の事前因子・cavity の除外先は正しい。主因は、短いループが複数ある因子グラフに
damping なしの BP を適用していることである。Bernoulli 事前分布によって更新写像と
初期値が変わり、振動が早く強く現れる例がある。ただし旧一様分布でも不安定な盤面がある。

実装には別の問題もある。小さい確率を直接掛けるため、振動の後でアンダーフローが発生する。
その結果の `[0,0]` を「制約が矛盾」と表示し、計算を続けられる状態になっていた。
この表示を「正規化失敗」に修正し、その時点で追加更新を止めるようにした。
正規化できない周辺確率を地雷確率0として表示しない。BP の非収束やアンダーフローを
盤面に解がない証拠として扱ってはならない。

## 更新式の照合

ブラウザ実装は

$$
m_{i\to a}(x_i)\propto P_0(x_i)
\prod_{b\in\partial i\setminus a}m_{b\to i}(x_i),\qquad
b_i(x_i)\propto P_0(x_i)\prod_{a\in\partial i}m_{a\to i}(x_i)
$$

と、和の制約に従った因子→変数更新を行っている。事前因子はそれぞれ1回であり、
因子→変数側に二重に掛けていない。1サイクルは、全変数メッセージを更新した後、
全因子メッセージを更新するスケジュールである。

独立の参照実装では確率の積を使わず、対数メッセージをそのまま保持し、
因子更新を地雷数についての dynamic programming と log-sum-exp で計算した。
ブラウザ実装とのメッセージ差は、資料例・ρ=1/3 の最初の10サイクルで最大
`1.55e-15`、ρ=1/2 で `3.33e-15` だった。
木上の `x1+x2=1, x2+x3=1` では、解010と101の事後確率1−ρとρから得られる
厳密周辺確率 `[ρ,1−ρ,ρ]` と一致することも検証した。

不安定な写像では微小な丸め誤差が増幅されるため、長時間の軌道は演算順序・実装によって変わる。
ブラウザと Python の長時間軌道の違いだけで、更新式の誤りとは判断できない。

## 「例を読み込む」での再現

変数順は上左・上右・中央・下左・下右。4制約は

```
x1 + x2 + x3 = 1
x1 + x3 + x4 = 1
x2 + x3 + x5 = 2
x3 + x4 + x5 = 2
```

であり、解は00101と01011の2個。事後確率はそれぞれ1−ρとρ、
中央の厳密地雷確率は `1−ρ`、`Zρ=ρ²(1−ρ)²` である。
ρ=1/3なら中央は2/3、分配関数は4/81であり、事後分布は正常に定義できる。

| サイクル | 中央の BP 地雷確率（ρ=1/3） |
| --- | ---: |
| 1 | 0.888889 |
| 2 | 0.333333 |
| 3 | 0.998094 |
| 4 | 0.262940 |

直接確率を掛けるブラウザ版は19サイクル目に正規化失敗する。
独立の対数空間版では19サイクル目でも全メッセージの対数値が有限であり、
中央の対数 odds は約8651。それでも振動は残り、100サイクル目の最大メッセージ差は1となる。
したがって、アンダーフローを防ぐだけでは振動そのものは解消しない。

旧一様分布は、同じグラフの推論ρを1/2にすれば比較できる。
その場合、この例は中央確率が約1/2に長く留まるが、丸め誤差をきっかけに不安定化しうる。
「最初の数サイクルで安定して見える」ことと、安定な fixed point の存在は区別する必要がある。

## 同じ盤面集合での旧・新測度の比較

資料例と同じ十字の開示 mask を固定し、未開示5セルの32配置を全列挙した。
各配置を生成する確率は Bernoulli(生成ρ)で重み付けし、同じ配置・同じ clue に対して
旧測度（推論ρ=1/2）と新測度（推論ρ=生成ρ）を比較した。
100サイクル以内・最大メッセージ差 `1e-10` を停止基準としたとき、
その停止より前にゼロ正規化へ至った配置の生成確率は次のとおり。

| 生成ρ | 旧一様測度 | 新 Bernoulli 測度 |
| --- | ---: | ---: |
| 0.10 | 9.81% | 11.43% |
| 0.30 | 25.41% | 34.23% |
| 1/3 | 27.16% | 23.87% |
| 0.50 | 31.25% | 31.25% |
| 0.80 | 18.56% | 23.68% |

これは特定の開示 mask と停止条件による再現実験であり、全盤面の非収束率ではない。
事後分布の変更で不安定化する場合はあるが、常に悪化するという結果でもない。
ρ=1/2で旧・新測度は一致する。

## 対策と精度の区別

参照実装で old message を20%保持する probability damping
`m_new = 0.2*m_old + 0.8*m_BP` を両方向に適用すると、資料例・ρ=1/3の振動は抑制された。
Python版でも damping=0 は19反復で正規化失敗、damping=0.2は約30反復で収束した。
ただし収束した中央の確率は約1であり、厳密値2/3とは異なる。
loopy BP の数値的収束と事後確率の正確さは別の問題である。

改善の候補は、damping の選択肢、対数メッセージの保持、最大メッセージ差・反復回数の表示。
いずれも正しい posterior を変えずに数値計算を改善するが、
ループのあるグラフでの収束や Exact との一致を保証しない。
調査時点のブラウザの計算は damping なしであり、調査のために測度や既定の更新式は変えていない。
その後、アプリに damping のオン／オフと係数設定を追加した。既定はオフで、
オンの場合はこの節と同じ probability damping を両方向に適用する。
